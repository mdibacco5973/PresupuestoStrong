# Agent Project Skills & Guidelines

## 1. Project Overview
- **Name:** Quote (Carpentry Quotation System)
- **Tech Stack:** Next.js (App Router), Tailwind CSS v4, shadcn/ui, TypeScript, Prisma ORM, MySQL.
- **Language:** Strictly English nomenclature for all code, database tables, and comments.

## 2. Directory Structure (Reserved Folder Names)
- `app/`: Next.js App Router. Contains all routes (`page.tsx`, `layout.tsx`, `api/`).
- `components/ui/`: Reusable, atomic UI components generated by shadcn/ui.
- `components/`: Higher-level application components (e.g., forms, tables, specific feature components).
- `lib/`: Utility functions and shared configuration (e.g., `utils.ts`, `prisma.ts`).
- `app/woods/`: Woods management CRUD.
- `app/parts/`: Parts management CRUD.
- `app/actions/`: Server Actions for database operations (`wood.ts`, `part.ts`).
- `prisma/`: Prisma schema (`schema.prisma`) and migrations.
- `public/`: Static assets.

## 3. Implemented Modules
### 3.1 Woods (Maderas)
- CRUD for wood inventory.
- Handles Decimal to Number conversion for Client Components.
- Argentine locale formatting for prices ($ 0.000,00).

### 3.2 Piezas (Parts)
- CRUD para configuración de piezas de muebles.
- Campos: Nombre, Cantos (Boolean), y flags adicionales (Cuerpo, Bajo Mesada, Alacena, Fondo, Cajón, Laqueado).
- Mapeado desde la tabla `parts` al modelo `Part`.
- **Cambio Reciente:** El campo `Edges` ahora es `isEdges` (Boolean) en lugar de un número.

### 3.3 Piezas Extra (ExtraParts)
- CRUD para herrajes y accesorios adicionales.
- Campos: Nombre, Precio (Decimal), Ferretería (Boolean), Accesorio (Boolean).
- Mapeado desde la tabla `extraparts` al modelo `ExtraPart`.

## 4. Database Standards
- Use `db pull` to sync with existing MySQL schema.
- Map SQL table names (`@@map`) to PascalCase model names in Prisma.
- Convert `TinyInt` boolean flags in SQL to `Boolean` in Prisma.
- **Base UI:** Se utiliza la propiedad `render` en lugar de `asChild` para los disparadores de componentes (Triggers) para evitar el error de botones anidados en el DOM.
- **CRITICAL:** When running `prisma generate` on Windows, ensure the dev server is stopped to avoid `EPERM` lock on query engine DLLs.

## 5. UI Standards
- **Tablas:** Todas las tablas deben incluir ordenamiento (Sorting) por las columnas principales (Nombre, Precio, etc.).
- **Sorting Implementation:** Se realiza en el cliente usando un estado `sortConfig` y los iconos `ArrowUpDown`, `ArrowUp`, `ArrowDown` de `lucide-react`.
- **Búsqueda (Search):** Todas las grillas deben incluir un campo de búsqueda reactivo que filtre por múltiples columnas (Nombre, Precio, Atributos, etc.).
- **Search Implementation:** Se usa un estado `searchTerm` y una lógica de filtrado `filteredItems` que se aplica sobre los datos ya ordenados.
- **Paginado (Pagination):** Las grillas con potencial de tener muchos registros deben incluir un paginado (ej: 10 items por página).
- **Pagination Implementation:** Se usa un estado `currentPage` y lógica de `slice` sobre los items filtrados. La búsqueda debe resetear la página a 1.

## 6. Operations & Guidelines
- **Nomenclature:** Always use English for file names, component names, variable names, database schema, and commit messages.
- **Dependencies:** If a new library or tool needs to be installed, **PROMPT THE USER** or notify them before doing so. 
- **Database:** Prisma ORM is used with MySQL. When altering the database, always update `prisma/schema.prisma` first, then run `npx prisma db push` or `npx prisma migrate dev`, asking the user to ensure the database is running or confirm credentials.
- **Self-Updating Skills:** Whenever a significant architectural change or new module is added, update this `AGENT_SKILLS.md` file to reflect the new state of the repository.

## 7. Current Modules
- **Woods (CRUD):** 
  - Prisma Model: `Wood` (Mapped to `woods` table in MySQL).
  - Contains fields for dimensions (Thickness, Length, Width, SurfaceArea), Price, and flags (IsBack, IsDrawer, IsDefaultWood).
  - **SurfaceArea:** Automatically calculated in the client as `Length * Width` to represent mm².
  - **Recordatorio:** A derived UI field in the table that shows status badges (Vió, Revisó, Olvidó, etc.) based on the `dateUpd` field, identical to the Costs module.
  - **Single Default Wood:** Server-side validation ensures only one wood can be marked as default via transactions. Additionally, the client component includes an interactive validation: clicking the checkbox prompts the user if another wood is already set as default.
- **Parts (Piezas):**
  - **Dynamic Formulas:** Supports `formulaLength` and `formulaWidth` using variables:
    - `L`: Furniture Length (Largo)
    - `A`: Furniture Width (Ancho/Altura)
    - `P`: Furniture Depth (Profundidad)
    - `E`: Wood Thickness (Espesor)
- **Furniture (Muebles):**
  - **Calculation Engine:** Automatically calculates individual piece dimensions and the total **Furniture Price** by evaluating Part formulas against the furniture's dimensions and the default wood's thickness and price.
  - **Full Price Breakdown:** The configuration tables for **Parts**, **Hardware**, and **Costs** display the calculated **Unit Price** and **Subtotal** for each item in real-time.
- **ExtraParts (CRUD):** 
  - Prisma Model: `ExtraPart` (Mapped to `extraparts` table).
  - Contains fields for Name, Price, and categories (IsHardwareStore, IsAccessory).
  - **Recordatorio:** A derived UI field in the table that shows status badges (Vió, Revisó, Olvidó, etc.) based on the `dateUpd` field, consistent with Woods and Costs.
- **Costs (CRUD):**
  - Prisma Model: `Cost` (Mapped to `costs` table).
  - Contains fields for Name, Price, and DateUpd (auto-managed).
  - Includes full UI features: Search, Sort, and Pagination.

### 3.4 Furniture (Muebles)
- CRUD for furniture configuration.
- **Price Calculation:** `hardwarePrice`, `costPrice`, and `furnitureTotal` are automatically calculated in the client via `useEffect`.
- **FurnitureTotal:** Sum of `furniturePrice` + `hardwarePrice` + `costPrice`.
- **Read-only Fields:** Calculated totals are displayed in read-only formatted fields in the form.
- **Main Table:** Displays `Code`, `Name`, `Dimensions`, `Furniture Price`, `Hardware Price`, `Cost Price`, and `Furniture Total`.
- **Data Sync:** Uses Prisma transactions to update related configurations.
- **Images:** Handles base64 image storage in a `LongBlob` field.

### 3.5 Clients (Clientes)
- CRUD for client management.
- **Prisma Model:** `Client` (Mapped to `clients` table in MySQL).
- **Fields:** Name (client_name), Email, Phone, userCreatedId, userUpdatedId.
- **Search & Sort:** Implemented reactively in the client for all main fields.
- **Pagination:** Handles 10 items per page.

### 3.6 Quotes (Presupuestos)
- CRUD for project quotes/budgets.
- **Prisma Model:** `Quote` and `QuoteDetail` (Mapped to `quotes` and `quotedetails`).
- **BigInt Support:** Handles BigInt to String serialization for client-side consumption.
- **Exchange Rate Logic:** Automatically calculates USD costs and prices when ARS values or Exchange Rate are updated.
- **Nested CRUD:** Implements a tabbed interface in the form to manage multiple `QuoteDetail` items (Furniture) per quote.
- **Auto-Fill:** Selecting a furniture item in the details editor automatically pre-fills its dimensions and calculated price.
- **Data Integrity:** Uses Prisma transactions to ensure atomicity when updating a quote and its related details.
- **Status Management:** Includes color-coded status badges (Pendiente, Aprobado, Rechazado, Finalizado).
- **Client Relationship:** Links each quote to a specific client, displaying the client name in the main table.
- **UI Consistency:** The Quotes module follows the exact design pattern of the Furniture module, using custom button-based tabs, unified grid layouts, and consistent table styling. In the items tab, the "Total" column represents the multiplication of quantity and unit price.
- **Responsive Table:** Includes horizontal scrolling for mobile usability.
- **Surface Calculation (Laqueado):** Automatically calculates the total front surface area (m²) of all furniture pieces marked as `isFront`.
- **Intelligent Item Merging:** The system automatically groups identical furniture and service items (hardware, finishes, labor, extra costs) into a single row. It sums quantities and updates subtotals, preventing redundant entries in the budget.
- **Duplication Action:** Implements a one-click duplication feature for quotes, cloning the entire configuration (furniture, parts, hardware, etc.) into a new record with the suffix "(Copia)".
- **Flexible Data Schema:** The database schema allows `furnitureId` to be optional in detail tables, supporting "global" or grouped items that aren't tied to a specific furniture piece.
- **Robust Serialization:** Server actions explicitly convert all `Decimal` and `BigInt` values to `Number` and `String`, respectively, avoiding spread operators to ensure clean objects for Next.js Client Components.
- **Full 8-Page PDF Presentation:** Implements a comprehensive 8-page PDF generator using `jspdf` and `jspdf-autotable`. The document mimics the "Strongwood" corporate presentation, including:
  - **Cover Page:** Sage green background with brand logo and project title.
  - **Institutional Content:** "Who We Are" and "How We Work" sections.
  - **Dynamic Budget (Page 4):** Lists furniture items, current date, and a consolidated "Logística, traslado e instalación" line that sums hardware, finishes, and labor costs.
  - **Technical Annex:** Dynamically lists the names of all wood types used in the project.
  - **Complementary Services:** Automatically lists additional costs/extras.
  - **Legal & Branding:** Includes materials, brand logos, conditions, and contact info.
- **Standardized Currency Formatting:** All monetary values (Costo/Precio ARS and USD) are displayed using the Argentine locale (`es-AR`), which uses dots for thousands and commas for decimals (e.g., `2.119.578,34`). This formatting is applied consistently across the dashboard, forms, and PDF exports.
- **Dynamic Furniture Pricing:** The unit price of each furniture item in the budget is calculated dynamically. If the user changes the wood assigned to a piece in the "Piezas" tab, or modifies the furniture dimensions, the unit price in the "Muebles" tab is automatically recalculated to reflect the new material costs while maintaining fixed costs (hardware, labor, etc.).
- **Locked Calculated Fields:** Calculated fields in the quote form (like laqueado quantity) are read-only to maintain calculation integrity.
- **Costo ARS Calculation:** The total cost (Costo ARS) is automatically calculated by summing the total prices of all items across the following tabs: Muebles (Furniture), Herrajes (Hardware), Acabados (Finishes), Mano de Obra (Labor), and Costos Extras (Additional Costs). This ensures that all components and services are reflected in the base cost before applying profit.
- **Real-time Piece Dimensions:** The Pieces tab in the quote form displays the calculated dimensions for each piece in a unified "Medidas (LxA)" column (Longitud x Ancho), evaluating formulas dynamically based on the associated furniture's dimensions and assigned wood thickness.
